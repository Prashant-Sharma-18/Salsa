# Deploying LoyalLoop on Render

`render.yaml` in the repository root is a Render Blueprint. It creates:

| Resource | Type | Purpose |
|---|---|---|
| `loyalloop-web` | Web service (Docker) | API + website. Runs database migrations on start. |
| `loyalloop-email-worker` | Background worker | Sends queued emails (`flask email-worker`) |
| `loyalloop-daily-jobs` | Cron job, 09:00 UTC | Points expiry, birthday bonuses, balance reconciliation |
| `loyalloop-db` | PostgreSQL 16 | Main database, with Render's daily backups |
| `loyalloop-redis` | Key Value (Redis) | Rate limits shared across web processes |

Rough cost at the time of writing is about $7 for each starter service and about $6–7 for the basic database. The Redis free tier is enough. Check Render's pricing page for current numbers.

## Before you start: email

New users verify their email, staff invitations are sent by email, and customers sign in with emailed links, so email delivery needs to be working before real use. You need SMTP details from one of these providers:

| Option | Signup | Sending address | Notes |
|---|---|---|---|
| **Domain + Postmark** (recommended) | Needs an address on your own domain | `no-reply@yourdomain.com` | Best deliverability for sign-in links. A free mailbox for the domain can come from Zoho Mail or Cloudflare Email Routing. |
| **Brevo** | Gmail accepted | Your verified Gmail address to start; switch to a domain later | Free for 300 emails a day. Gmail "from" addresses can land in spam, so treat this as a pilot setup. |
| Amazon SES / SendGrid / Mailgun | Varies | Domain recommended | All work over SMTP |

SMTP settings by provider:

- **Postmark:** `SMTP_HOST=smtp.postmarkapp.com`. Use the server API token as both `SMTP_USERNAME` and `SMTP_PASSWORD`.
- **Brevo:** `SMTP_HOST=smtp-relay.brevo.com`. Use your SMTP login as `SMTP_USERNAME` and the SMTP key as `SMTP_PASSWORD`. Both are under *SMTP & API* in Brevo.

All providers use `SMTP_PORT=587` and `SMTP_SECURITY=starttls`.

## Steps

1. **Render dashboard → New → Blueprint.** Connect GitHub, choose `Prashant-Sharma-18/Salsa`, and confirm. Render reads `render.yaml`.
2. **Fill in the prompted values:**
   - `PUBLIC_BASE_URL`: `https://loyalloop-web.onrender.com` for now (check the exact name Render assigns). Change it to your own domain later.
   - `PLATFORM_ADMIN_EMAILS`: your email address.
   - `EMAIL_FROM`, `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`: from your email provider.
   - `SENTRY_DSN`: optional. Leave it blank if you don't use Sentry.
3. **Apply.** The first deploy builds the Docker image, which takes about 5–10 minutes. Then open `https://<your-service>.onrender.com/api/v1/health`, which should return `{"status":"ok","database":"ok"}`.
4. **Create your account** on the site with the email from `PLATFORM_ADMIN_EMAILS`, and click the verification link in your inbox. You are now a platform admin.
5. **Turn on two-factor** under *Account & privacy*. This is required before the `/admin` console will open.
6. **Custom domain (optional):** web service → *Settings → Custom Domains*. Add `app.yourdomain.com`, create the DNS record Render shows you, then update `PUBLIC_BASE_URL` in the `loyalloop-shared` environment group.

## Settings that are deliberately fixed

These guards are enforced by the app itself, so a misconfigured deploy fails fast instead of running unsafely:

- `APP_ENV=production`
- `COOKIE_SECURE=true`
- `DEMO_MODE=false`: no demo data or demo logins.
- `ADMIN_REQUIRE_MFA=true`
- `TRUSTED_PROXY_COUNT=1`: Render's load balancer sits in front of the app.
- `SECRET_KEY` is generated by Render and shared by all services. Don't change it after launch: two-factor secrets are encrypted with a key derived from it, unless you set a separate `MFA_ENCRYPTION_KEY`.

## Turning on payments later

1. Create the Starter, Growth and Pro products in Stripe, each with a monthly price.
2. Add these to the `loyalloop-shared` group:
   - `BILLING_PROVIDER=stripe`
   - `STRIPE_SECRET_KEY`
   - `STRIPE_PRICE_STARTER`, `STRIPE_PRICE_GROWTH`, `STRIPE_PRICE_PRO`
   - `STRIPE_WEBHOOK_SECRET`
3. In Stripe, add a webhook pointing to `https://<your-domain>/api/v1/billing/stripe/webhook` with these events:
   - `checkout.session.completed`
   - `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`
   - `invoice.payment_failed`
4. Test everything in Stripe **test mode** first.

## If something goes wrong

- **A service won't start:** check its logs. A missing or unsafe setting fails at startup with a clear `RuntimeError`, for example `EMAIL_PROVIDER=smtp requires SMTP_HOST`.
- **Emails aren't arriving:** check the `loyalloop-email-worker` logs. Failed sends are retried up to 5 times, and the error is stored on the outbox row.
- **The daily job fails:** if `flask reconcile` exits with code 1, a cached balance doesn't match the ledger. Investigate before making manual adjustments.
